# DataLY

نظام معالجة فواتير الموردين وتصديرها لمنظومة السهل — للسوق الليبي.

بدأ المشروع كأداة بايثون/pandas لسطر الأوامر (لا تزال موجودة بجذر هذا المستودع، شغّالة
ومختبرة باستقلالية — راجع [التشغيل محلياً](#التشغيل-محلياً) تحت)، وأُعيد بناؤه بالكامل
كتطبيق ويب متعدد المتاجر: **منشور فعلياً وشغّال حياً الآن.**

## 🔗 الرابط الحي

- **التطبيق:** https://data-ly.vercel.app
- **API (توثيق Swagger تفاعلي):** https://dataly-backend.onrender.com/docs

> Render (الاستضافة المجانية للباك إند) ينام بعد فترة خمول — أول طلب بعد فترة راحة قد
> ياخذ 30-50 ثانية لحد ما يصحى. الطلبات اللي بعده عادية وسريعة.

## نظرة عامة

DataLY يودّي فاتورة مورد خام (إكسل) عبر خط أنابيب كامل: رفع → تنظيف وتصنيف تلقائي →
جلسة استلام تاجر (باركود/صلاحية/سعر بيع) → تسوية الأصناف مقابل فهرس مشترك بين كل
المتاجر (بموافقة بشرية دائماً) → دمج بالمخزون التراكمي → تصدير ملف جاهز للاستيراد
المباشر بمنظومة "السهل" (Alsahl POS).

كل شاشة بالتطبيق مبنية فعلياً ومتحقَّق منها يدوياً وحياً — سطح مكتب، تابلت، وموبايل —
ضد قاعدة بيانات Postgres حقيقية بالإنتاج، مو بيئة تجريبية منفصلة.

## المكدس التقني

| الطبقة | التقنية |
|---|---|
| الواجهة | React 18 · TypeScript · Vite · TanStack Query · Tailwind CSS |
| الباك إند | FastAPI · SQLAlchemy · Alembic · JWT auth |
| قاعدة البيانات | PostgreSQL (Supabase) |
| الاستضافة | Vercel (الواجهة) + Render (الباك إند) |

## خط أنابيب الفاتورة

```
رفع فاتورة → تنظيف وتصنيف تلقائي → جلسة استلام التاجر → تسوية الأصناف
→ دمج بالمخزون التراكمي → تصدير ملف Alsahl
```

كل انتقال بين المراحل يصير بفعل صريح عبر نقطة API مخصصة — ولا مرحلة تُتخطى. التفاصيل
الكاملة لكل نقطة ولمنطق كل مرحلة بـ[`backend/README.md`](backend/README.md)، وخطة
إعادة البناء الكاملة (القرارات المعمارية، خريطة الجداول، المراحل) بـ
[`docs/REBUILD_PLAN.md`](docs/REBUILD_PLAN.md).

## قرارات هندسية محفوظة من الأداة الأصلية

منطق العمل مو اعتباطي — كل قرار محفوظ نتيجة تجربة حقيقية ضد فواتير حقيقية أثناء بناء
الأداة الأصلية، ونُقل حرفياً للباك إند بدل ما يُعاد اختراعه:

- **الباركود هو مرساة الهوية بالتسوية** — تسمية الصنف تختلف بصيغ كثيرة حسب المورد،
  الباركود لأ.
- **ولا تطابق تسوية يُطبَّق تلقائياً، مهما كانت نسبة التشابه** — قرار بشري صريح دائماً
  (قبول/رفض/تسمية يدوية)، لأن تطابقات عالية الثقة طلعت خاطئة فعلياً أثناء الاختبار
  (زي "كورن"≈"كلور" بنسبة تشابه 85.7%).
- **`per_box` (عدد القطع بالعبوة) يبقى `NULL` صراحة لو غير معروف من الفاتورة** — أبداً
  قيمة افتراضية `1` ملفّقة توهم إنها بيانات حقيقية وتُفسد حسابات الصناديق لاحقاً.
- **ملف التصدير يُعاد بناؤه من قاعدة البيانات وقت كل تنزيل، مو يُقرأ من القرص** — قرص
  Render المجاني مؤقت وينمسح بإعادة النشر؛ هذا بق حقيقي انكشف واتصلح بعد النشر الفعلي
  (راجع تفاصيله بـ[`backend/README.md`](backend/README.md)).

## التشغيل محلياً

### تطبيق الويب (الجزء النشط حالياً)

```bash
# الباك إند
cd backend
pip install -r requirements.txt
cp .env.example .env   # عبّي DATABASE_URL/JWT_SECRET
python -m alembic upgrade head
uvicorn app.main:app --reload --port 8000

# الواجهة (بترمنال ثاني)
cd frontend
npm install
cp .env.example .env
npm run dev
```

تفاصيل الإعداد الكاملة (المستخدم الإداري، بنية المجلدات، نقاط الـAPI): راجع
[`backend/README.md`](backend/README.md) و[`frontend/README.md`](frontend/README.md).

### الأداة الأصلية لسطر الأوامر (ما زالت مستقلة وشغّالة طول فترة الانتقال)

```bash
pip install -r requirements.txt

# 1) معالجة فاتورة جديدة
python main.py invoice.xlsx

# 2) أرسل data/session_template.xlsx للتاجر، أو شغّل واجهة الاستلام:
streamlit run session/receiving_app.py

# 3) بعد ما يخلّص التاجر، انقل session_output.xlsx لمجلد data/

# 4) وحّد الأصناف مقابل قاعدة الأصناف وادمج وصدّر لملف السهل
python main.py --merge
```

الناتج النهائي: `output/output_alsahl.xlsx` — ارفعه في شاشة "فاتورة مشتريات" بمنظومة
السهل. تفاصيل قرارات التصميم بـ`ARCHITECTURE.md` وتاريخ الإصدارات بـ`CHANGELOG.md`.

## الاختبارات


## هيكل المستودع

```
DataLY/
├── backend/          ← FastAPI + PostgreSQL — منشور على Render
├── frontend/          ← React + TypeScript — منشور على Vercel
├── docs/                ← خطة إعادة البناء الكاملة (REBUILD_PLAN.md)
├── extractors/ transformers/ session/ fusion/ adapters/ utils/
│                          ← منطق الأداة الأصلية لسطر الأوامر (نفس المنطق منقول
│                             لـ backend/app/core_logic/ بالتطبيق المنشور)
├── tests/                    ← اختبارات pytest للأداة الأصلية
└── data/ output/               ← ملفات عمل الأداة الأصلية
```
